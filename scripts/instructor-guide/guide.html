이 교재의 쓰임

강의에서 다루는 내용 전체를 강사가 미리 이해하고, 강의 중에는 해당 세션을 펼쳐 진행할 수 있게 정리했다. 세션마다 목표 → 진행표 → 강의 내용(개념과 배경) → 실습·시연 절차와 정답 → 자주 나오는 질문 → 주의할 점 순서다. 말할 문장(대본)은 넣지 않았다.

정답이 들어 있으므로 참석자에게 배포하지 않는다. 참석자용은 프롬프트 모음집 1장과 실습 파일이다.

강의 목표와 반복할 메시지

강의가 끝나면 참석자가 다음 날 자기 업무에 Claude를 하나 이상 쓸 수 있다.

  1. 역할 + 상황 + 요청 + 출력 형식으로 쓰면 결과가 좋아진다.
  2. AI 결과는 초안이다. 숫자·품번은 원본과 대조한다.
  3. 가상 자료로 연습하고, 실제 자료는 회사 규칙 안에서 쓴다.

강의 내용

왜 결과부터 보여주는가

사무직 참석자는 AI에 대해 "신기하지만 내 일과는 멀다"고 느끼는 경우가 많다. 자기 회사 업종(자동차 부품)에 맞춘 품번과 화면으로 바코드를 찍으면 재고가 바뀌는 장면을 먼저 보면, 이후 세션의 작은 실습이 어디로 이어지는지 이해한다.

완성품 시연 절차

  1. 대시보드: 전체 품목, 안전재고 미달, 오늘 입고·출고 숫자를 보여준다.
  2. 입고 화면으로 가서 USB 스캐너로 라벨을 찍는다 → 부품이 "선택됨"으로 뜬다 (스캔은 선택만 하고 저장은 [입력]으로 한다는 점을 짚는다).
  3. 수량을 넣고 [입력] → "입고 완료"와 현재고가 바뀐 것을 보여준다.
  4. 대시보드로 돌아가 숫자가 바뀐 것을 확인한다.
  5. 스마트폰으로 같은 사이트를 열어 방금 기록이 보이는 것을 보여준다 (구글 시트 연동). 자세한 설명은 세션 5로 미룬다.

생성형 AI는 어떻게 답을 만드는가

나쁜 예 납기 지연 메일 써줘는 받는 사람, 이유, 일정을 모르니 AI가 빈칸을 지어내거나 일반적인 글을 쓴다. 정보를 줄수록 다시 고칠 일이 줄어든다.

한 단계 더: 결과를 좋게 하는 요령

  • 예시를 하나 준다: "이런 식으로: …"라고 원하는 모양을 보여주면 가장 빠르다.
  • 모르면 질문하게 한다: "빠진 정보가 있으면 먼저 질문해줘."
  • 형식을 정한다: 표, 번호 목록, 3문장, A4 반 장.
  • 대화로 고친다: 한 번에 완벽하게 쓰려 하지 말고 "더 짧게", "표로", "상사에게 보고하는 말투로"처럼 이어서 고친다.
  • 잘 된 프롬프트는 저장한다: 다음에 [ ]만 바꿔 다시 쓴다 (프롬프트 모음집의 방식).

Claude가 엑셀 파일을 다루는 방식

데이터 정리가 왜 중요한가

엑셀의 찾기·합계 함수는 글자가 정확히 같아야 같은 것으로 본다. SK-AD-001과 sk-ad-001, SK-AD-001 (뒤에 공백)은 사람 눈에는 같지만 함수에는 다른 값이다. 그래서 정리 안 된 목록에서는 단가를 못 찾고(#N/A), 합계가 빠지고, 중복이 생긴다. 실습 2에서 이 현상을 직접 보여준다.

"정리해줘"보다 규칙이 나은 이유

"정리"의 기준은 사람마다 다르다. 규칙 없이 시키면 결과가 사람마다, 할 때마다 달라진다. 규칙 7가지(부록 A-2)를 적어 주면 결과가 일정해지고, 이 규칙 목록이 그대로 팀의 데이터 입력 기준이 된다. 또 1,5처럼 사람도 헷갈리는 값(15인가 1,500인가)은 AI도 추측하면 안 되므로 "애매하면 지우지 말고 표시"하라고 시킨다.

찾아오기 함수: XLOOKUP, VLOOKUP, INDEX/MATCH

함수쓸 수 있는 버전특징
XLOOKUP엑셀 2021, Microsoft 365가장 쉽다. 찾을 값, 찾을 범위, 가져올 범위, 없을 때 값. 왼쪽 열도 가져올 수 있다
VLOOKUP모든 버전찾는 열이 범위의 맨 왼쪽이어야 한다. 마지막 인수를 FALSE(정확히 일치)로 꼭 넣는다. 빼면 비슷한 값을 찾아 틀린 답이 나올 수 있다
INDEX/MATCH모든 버전MATCH로 몇 번째 행인지 찾고 INDEX로 가져온다. 방향 제약이 없다

프롬프트에 "엑셀 2016에서 쓸 수 있는 함수로"처럼 버전을 적으면 그 버전에 맞는 함수를 받는다. 버전은 엑셀 메뉴 파일 → 계정 → 정보에서 확인한다. XLOOKUP이 없는 버전에서 쓰면 #NAME? 오류가 난다.

조건별 합계: SUMIFS

SUMIFS(더할 범위, 조건 범위1, 조건1, 조건 범위2, 조건2, …). 품번이 같고 날짜가 9월 1일~30일인 수량만 더할 때 날짜 조건은 ">="&DATE(2026,9,1)처럼 비교 기호와 날짜를 이어 붙인다. 출고일이 글자로 저장돼 있으면 날짜 조건이 맞지 않아 0이 나오므로, 실습 파일의 출고일은 실제 날짜 형식으로 넣어 두었다.

매크로는 엑셀 안에서 돌아가는 작은 프로그램이다. 매일 하는 서식 맞추기, 시트 복사, 인쇄 설정 같은 반복 작업을 버튼 하나로 만든다. 예전에는 "매크로 기록"으로 만들거나 VBA를 배워야 했는데, 이제는 원하는 동작을 말로 설명하면 Claude가 코드를 써 준다.

  1. Alt + F11 → VBA 편집기 → 삽입 → 모듈 → 코드 붙여넣기

OCR과 AI 사진 읽기의 차이

OCR(광학 문자 인식)은 사진 속 글자를 텍스트로 바꾸는 기술이다. 예전 OCR은 글자만 뽑아서 표의 칸 구조나 "이 숫자가 수량인지 단가인지"를 잘 구분하지 못했다. Claude 같은 AI는 사진을 보고 표의 구조와 각 칸의 의미까지 이해해서 "수량 열만", "단가는 빼고"처럼 원하는 형태로 정리할 수 있다. 다만 흐린 글자를 그럴듯하게 채울 수 있어 검수가 반드시 필요하다.

프롬프트의 세 가지 장치

  • 추측 금지: "읽기 어려운 칸은 추측하지 말고 '확인 필요'". 그럴듯한 오답을 막는 가장 중요한 한 줄이다.

  3. 품번: 한 글자만 틀려도 다른 부품이 된다. 특히 0과 O, 1과 I, 5와 S, 8과 B.

품번 체계와 바코드

바코드는 품번 글자를 그대로 담는다. 그래서 품번 체계가 곧 바코드 설계다. 실습 품번 SK-분류-일련번호(예: SK-AD-001)는 다음 원칙을 따른다.

  • 영문 대문자·숫자·하이픈만 쓴다 (스캐너와 시스템 사이에서 깨지지 않는다).
  • 분류 코드로 무엇인지 알 수 있다 (AD 덕트, PD 페달, CS 케이스, RM 원자재, SB 부자재).
  • 일련번호 자릿수를 고정한다 (001, 002 … 정렬이 맞는다).
  • 세션 2의 정리 규칙과 같다: 정리된 품번이어야 라벨과 시스템이 맞는다.

USB 바코드 스캐너의 동작

일반 USB 스캐너는 키보드처럼 동작한다. 바코드를 읽으면 그 글자를 키보드로 친 것처럼 입력하고, 마지막에 Enter를 보낸다. 그래서 메모장, 엑셀, 웹페이지 어디에든 입력된다.

  • 한/영 상태가 한글이면 품번이 ㄴㅏ-ㅁㅇ-001처럼 들어간다. 영문 상태로 바꾼다.
  • 커서가 입력칸에 있어야 한다. 앱의 입고·출고 화면은 늘 스캔 칸에 커서를 둔다.
  • 끝에 Enter를 보내지 않도록 설정된 스캐너도 있다. 설명서의 설정 바코드로 바꿀 수 있다.

라벨 인쇄 요령

  • 바코드 좌우에 빈 여백(조용 영역)이 있어야 읽힌다. 라벨 끝까지 꽉 채우지 않는다.
  • 너무 작게 인쇄하면 막대가 뭉개진다. 처음에는 크게 인쇄해서 스캔해 보고 줄인다.
  • 라벨지(예: A4 3×8)를 쓸 때는 규격에 맞춰 달라고 요청한다.

아티팩트로 작은 프로그램 만들기

아티팩트는 Claude가 대화 옆 창에 바로 쓸 수 있는 결과물을 만드는 기능이다. 문서뿐 아니라 입력칸과 단추가 있는 작은 웹페이지도 만든다. 오늘은 "품번을 넣으면 바코드 라벨이 나오는 페이지"를 말로 설명해서 만든다. 고치는 것도 말로 한다.

실습 절차

  1. 부록 A-4의 프롬프트로 라벨 생성기를 만든다.
  2. 예시 품번 5개를 넣어 라벨이 나오는지, 바코드 아래 품번이 맞는지 확인한다.
  3. 다듬기 하나: "QR도 같이", "품명과 보관 위치도 표시", "A4 3×8 라벨지 크기로".
  4. 강사가 인쇄 → USB 스캐너로 메모장에 찍어 품번이 그대로 들어오는 것, 스마트폰 카메라로 QR을 읽는 것을 보여준다.
  5. 앱의 부품 관리 → 라벨 출력 결과와 비교해서 보여준다.

체크포인트 라벨 5개가 보이고 품번이 맞는가. 아티팩트가 안 되는 계정이면 강사 화면으로 진행한다.

이 앱을 만든 과정

  1. 회사 조사·강의 계획 → 요구사항 문서(PRD): 무엇을 만들지, 우선순위, 화면, 데이터 구조. 이 문서도 대화로 만들었다.
  2. 1단계: 서버 없이 브라우저에서 동작하는 웹페이지. 바코드 스캔, 입고·출고, 재고 현황, 이력, 부품 관리, 라벨 출력, CSV 내보내기.
  3. 테스트 먼저: 기능마다 "이렇게 동작해야 한다"는 자동 테스트를 먼저 쓰고 기능을 만들었다. 현재 단위 테스트 335개, 화면 테스트 34개가 매번 자동으로 돈다.
  4. 코드 리뷰: 다른 AI 에이전트가 검토해서 찾은 문제(여러 탭에서 기록이 지워지던 문제 등)를 고쳤다.
  5. 2단계: 구글 시트 연동(여러 기기가 함께 씀), GitHub Pages 배포(https 주소, 스마트폰 카메라), 서류 사진으로 입고(OCR), 새 부품 품번 제안.

사람이 한 일: 원하는 것을 말하기, 결정하기(예: "스캔은 선택만, 저장은 [입력] 단추로"), 결과 확인하기, 계정·키 설정. 코드는 직접 쓰지 않았다.

ERP·MES와 연결할 수 있나?

A-2. 세션 2 (엑셀)

실습 1 목록 정리

첨부한 엑셀의 '부품목록' 시트는 여러 사람이 입력해서 표기가 제각각이야. 아래 규칙으로 정리해서 엑셀 파일로 돌려줘.
1. 품번은 SK-분류-세자리번호 형식 (예: SK-AD-005). 대문자, 공백 없이.
2. 품번이 같은 행은 하나만 남겨.
3. 빈 행과 메모 행은 지워.
4. 단위는 EA, BOX, BAG 중 하나로.
5. 거래처는 (주), ㈜, 주식회사, 띄어쓰기를 빼고 회사 이름만.
6. 안전재고는 숫자만. 뜻이 애매한 값은 지우지 말고 '확인 필요' 열을 만들어 이유를 적어.
7. 등록일은 YYYY-MM-DD. 연도가 없으면 2026년.
마지막에 무엇을 몇 건 고쳤는지 표로 알려줘.

실습 2 함수

엑셀 [2016]에서 쓸 수 있는 함수로 알려줘. '부품목록' 시트 A열 품번으로 '단가표' 시트(A열 품번, B열 단가)에서 단가를 찾아 I열에 넣는 수식. 단가가 없으면 '단가 없음'이라고 나오게.
'출고내역' 시트에 출고일(A열), 품번(B열), 수량(C열)이 있어. '부품목록' J열에 품번별 2026년 9월 출고량 합계를 넣는 수식을 알려줘.
J열이 0이면 그 행 전체를 연한 빨강으로 칠하는 조건부 서식 만드는 방법을 단계별로 알려줘.

매크로 (강사 PC)

엑셀 VBA 매크로를 만들어줘. 현재 시트를 보고서 서식으로 바꾸는 매크로야.
1행 머리글은 굵게, 연한 파랑 배경. 모든 열 너비 자동 맞춤. F열과 I열은 천 단위 쉼표.
A4 가로로 한 페이지에 인쇄되게 설정. 처음 써 보는 사람을 위해 넣는 방법도 단계별로 알려줘.

A-3. 세션 3 (서류 사진)

첨부한 거래명세서의 품목 표를 읽어서 표로 만들어줘.
열: 귀사 품번, 공급사 코드, 품명, 규격, 단위, 수량
단가와 금액은 빼줘.
표 위에 명세서 번호, 거래 일자, 공급자 상호를 따로 적어줘.
읽기 어려운 칸은 추측하지 말고 '확인 필요'라고 적어줘.
이 표를 엑셀에 바로 붙여넣을 수 있게 탭으로 구분한 형식으로 다시 보여줘.
표의 행 수와 수량 합계를 알려줘. 그리고 서류 아래쪽 합계 칸에 적힌 수량과 같은지 비교해줘.

응용 A (sample-02, 부품목록도 첨부)

거래명세서의 품목 표를 1단계와 같은 열로 만들어줘. 귀사 품번이 빈 행은 함께 첨부한 부품목록에서 품명과 규격이 같은 부품의 품번으로 채우고, 그렇게 채운 칸은 '(추정)'이라고 붙여줘.

응용 B (sample-03, 부품목록도 첨부)

거래명세서의 품목 중 첨부한 부품목록에 없는 품목을 찾아줘. 그 품목을 새로 등록한다면 품번 체계(SK-분류-세자리번호)에 맞게 어떤 품번이 좋을지 이유와 함께 제안해줘.
